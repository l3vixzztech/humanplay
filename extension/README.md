# humanplay — Chrome extension (MV3)

Milestone 3: the **chess.com DOM adapter**. A content script reads the live game
state (position, full move history, orientation, user color) straight from the
chess.com page and broadcasts it as a `GameState` message. The side panel shows a
"chess.com game state" card and can record sanitized JSON snapshots for the
fixture corpus.

Still deliberately absent: any `/analyze` call (M4), the arrow overlay (M5), TTS
(M6). Pixel recognition is parked (`../parked/image-recognition/`); the
capture-source abstraction and the PNG recorder remain as **debug tools**.

## Load it (dev)

1. Start the helper server (optional for M3, needed for an "online" chip and M4):
   ```bash
   cd server && .venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8765
   ```
2. `chrome://extensions` → Developer mode ON → **Load unpacked** → this
   `extension/` directory → pin **humanplay**.
3. Open a chess.com game (a bot game is fine), **click the humanplay toolbar
   icon** → the side panel opens; the state card fills in within ~1 s.
4. Move a piece — the card updates on every change (debounced 150 ms).

## Structure

```
manifest.json                    MV3 0.2.0: content_scripts + web_accessible_resources for chess.com only
icons/                           generated by tools/make_icons.py
src/content/chesscom-adapter.js  the content script: board/position/history/flip/color reading + snapshot
src/content/board-dom.js         pure parsing helpers (class tokens -> piece/square, board field, sanity)
src/content/move-history.js      pure SAN list -> UCI + exact FEN replay (imports vendored chess.js)
src/capture/capture-source.js    LOCKED capture interface + sources   (debug tool since M3)
src/background/service-worker.js toolbar action -> side panel (that is all it does)
src/ui/sidepanel.{html,css,js}   state card, snapshot recorder, debug capture/recorder, health chip
vendor/chess.js                  pin 1.4.0 (BSD-2-Clause) + LICENSE + README
tools/make_icons.py              regenerates icons (stdlib only)
```

The content script is a **classic script** (MV3 limitation), so it has no
static imports: `board-dom.js`, `move-history.js` and `vendor/chess.js` are
loaded with `import(chrome.runtime.getURL(...))` and listed in
`web_accessible_resources` (chess.com origins only). The same module files run
unchanged in Node for the zero-dep unit tests.

## The chess.com adapter (M3)

What it reads, all verified against live chess.com on 2026-10-16 (probe
evidence: `../test/fixtures/chesscom/README.md` and `.../reference/`):

| Datum | Primary | Fallbacks |
|---|---|---|
| board element | largest displayed `wc-chess-board` / `#board-single` / `#board-play-computer` / `#board-analysis-board` / `.board` | — |
| position | `.piece` elements with `square-XY` classes (X = file digit a=1…, Y = rank digit 1…; absolute under flipping) | per-square containers with piece children; the FEN the board exposes (`board.game.getFEN()`, validated) |
| history | move-list nodes (`.node` in `wc-simple-move-list` / `wc-vertical-move-list` / `.move-list`…), timestamps `[data-move-list-el="timestamp"]` excluded, ordered by `data-node` ply | `board.game.getHistorySANs()` when no DOM list exists |
| flipped | `wc-chess-board.flipped` class | `board.state.isFlipped` |
| user color | bottom player's `clock-white`/`clock-black` token | `board.game.getPlayingAs()`; panel setting `settings.userColor`; flipped inference |

Every position strategy is verified by a **placement plausibility check**
(exactly one king per side, no pawns on rank 1/8, no duplicate squares, ≤ 32
pieces) — a strategy that parses but yields an impossible position is rejected
and the next one is tried. The log of which strategy won is in `strategyLog`
and is mirrored to `console.debug` (`[humanplay] position=… history=…`).

**Reconciliation (locked, `../docs/PROJECT.md`):** the board is the source of
truth for the position, chess.com's move list for the history. The SAN list is
replayed from the initial position with chess.js; if the replayed board field
differs from the DOM board field (or a move is illegal), the state carries a
`mismatch` object, the history is dropped for that update and `warnings`
explain any degraded metadata (`side to move unknown`, …). The panel renders
mismatch/warnings prominently.

**GameState** (full field list and semantics: `../docs/PROJECT.md`):

```js
{ ok, fen, movesUci, userColor, flipped, boardRect{x,y,w,h}, devicePixelRatio,
  gameUrl, gameId, ts, mismatch?, boardId, turn, positionSource, historySource,
  historyStatus, warnings[], strategyLog[], sessionSeq, resetDetected, … }
```

`boardRect` is the 8×8 play area in **viewport CSS pixels** (`getBoundingClientRect`
of the board element) plus `devicePixelRatio` — everything M5 needs to draw an
arrow on the real board.

Messages: the content script broadcasts `humanplay:chesscom-state` on every
change; the panel can send `humanplay:get-state` (Refresh button, on open) and
`humanplay:record-snapshot` (see below).

## Snapshot recorder (how real fixtures are produced)

Panel button **Record chess.com snapshot** → the content script serializes the
page into a JSON snapshot (board `outerHTML`, move list `outerHTML`, player
strips, extracted state, board rect, DPR, URL) with **usernames stripped**
(replaced by `user`), member links neutralised and avatar upload URLs removed.
The panel then:

1. downloads it as `chesscom-snapshot-<timestamp>.json` (always), and
2. best-effort `POST http://127.0.0.1:8765/snapshot` — if
   `test/tools/fixture_server.py` is running, the file is written **straight
   into `test/fixtures/chesscom-snapshots/`**.

From there `test/tools/adapter-proof.mjs` replays it through
`test/fixtures/chesscom/replay.html` and asserts the adapter parses the rebuilt
page into the recorded state. Protocol: `../test/fixtures/chesscom/README.md`.

## Side panel

- **Assistant toggle** — persisted in `chrome.storage.local` under `settings`
  (gates the M9 continuous loop).
- **chess.com game state card** — listening chip, board id, exact FEN, move
  count + history status, side to move, your color (+how it was detected),
  mismatch warning, warnings line, source/strategy line. **Refresh state** asks
  the active tab's content script. **fallback color** (`auto`/`white`/`black`)
  is the manual override when detection breaks on a page variant.
- **Debug tools (M2)** — **Capture now** (one frame through the locked
  capture-source abstraction) and **Record fixture (PNG)** (downloads the last
  frame via `chrome.downloads`). Screenshot data URLs are never written to
  storage; the last frame lives in memory only.
- **Server chip** — `GET http://127.0.0.1:8765/health` (2.5 s timeout).

## Permissions (important)

- `content_scripts` / `web_accessible_resources`: only
  `https://www.chess.com/*` and `https://chess.com/*`. **No `<all_urls>`** in
  the shipped manifest.
- `host_permissions`: only `http://127.0.0.1:8765/*` (`/health`, later
  `/analyze`, snapshot upload).
- Tab capture (debug tool) uses `activeTab`: Chromium requires **activeTab or
  `<all_urls>`** for `chrome.tabs.captureVisibleTab`
  (`permissions_data.cc`, `CanCaptureVisiblePage`, `kActiveTabOrAllUrls`); a
  narrow host permission is not enough. Clicking the toolbar icon on the tab is
  what grants it — which is also how the side panel opens.

## Boundaries

No Maia-3 code here, ever — the extension is a clean-room HTTP client for the
separate local server (`../docs/PROJECT.md`). The only vendored runtime file is
`vendor/chess.js` (BSD-2-Clause, pinned). No anti-detection features, no
Stockfish, no telemetry. The content script only reads; it never injects
anything into chess.com pages or modifies the page.

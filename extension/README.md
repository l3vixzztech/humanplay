# humanplay — Chrome extension (MV3)

Milestone 2: MV3 skeleton, the **locked capture-source abstraction**, tab capture
and a minimal side panel (toggle · capture · fixture recorder · server chip).
No board detection, no `/analyze` calls, no overlay, no TTS yet — those are
M3–M8.

## Load it (dev)

1. Start the helper server (optional for M2, needed for an "online" chip):
   ```bash
   cd server && .venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8765
   ```
2. Load the extension:
   - open `chrome://extensions`
   - enable **Developer mode**
   - **Load unpacked** → select this `extension/` directory
3. Pin **humanplay** (`█▛` checkerboard icon) to the toolbar.
4. Go to the tab you want to capture, **click the humanplay icon** → the side
   panel opens, then press **Capture now**.

## Capture interface (locked)

```js
import { getCaptureSource } from "../capture/capture-source.js";

const frame = await getCaptureSource().getFrame();
// {
//   dataUrl,    // "data:image/png;base64,…"  raw screenshot, PNG
//   width,      // px (CSS pixels of the captured tab)
//   height,     // px
//   capturedAt, // ISO-8601 string
//   source,     // "browser-tab"
//   tabUrl,     // best-effort, "" when the extension may not read the tab
//   tabTitle,   // best-effort, "" when the extension may not read the tab
//   tabId,      // present when known
// }
```

- `BrowserTabCaptureSource` — `chrome.tabs.captureVisibleTab`, self-throttled to
  one frame per 550 ms (Chrome caps the API at ~2 calls/second; continuous
  capture is M9).
- `DesktopCaptureSource` — throws `not implemented`; the seam exists so a
  desktop source can be added later without touching M3+ code (out of scope,
  see `../docs/PROJECT.md`).
- `getCaptureSource(kind = "browser-tab", options)` — factory. Downstream code
  must never call capture APIs directly.

## Capture permissions (important)

`chrome.tabs.captureVisibleTab` requires **either the `activeTab` grant or an
`<all_urls>` host permission**. A narrow host permission — even one that matches
the page, like `http://127.0.0.1:8765/*` — is *not* sufficient; Chromium checks
this in `extensions/common/permissions/permissions_data.cc`
(`CanCaptureVisiblePage`, `CaptureRequirement::kActiveTabOrAllUrls`).

This extension stays on `activeTab`, i.e. **no broad host permissions**:

- `permissions`: `activeTab`, `storage`, `sidePanel`, `downloads`
- `host_permissions`: `http://127.0.0.1:8765/*` — only for `GET /health`
  (and later `POST /analyze`) via `fetch`, never for capture
- the toolbar action calls
  `chrome.sidePanel.setPanelBehavior({openPanelOnActionClick: true})`, so
  clicking the icon opens the panel *and* grants `activeTab` for that tab
  (documented Chrome behaviour; confirm end-to-end on a real site in M3)

If the user presses **Capture now** without a grant, the panel shows exactly
that error and how to fix it.

## Side panel (M2 scope)

- **Assistant on/off toggle** — persisted in `chrome.storage.local` under
  `settings` (the switch is already persisted; it will gate the M9 capture loop).
  Screenshot data URLs are **never** written to storage (they are large and may
  contain page content); the last frame lives in memory only.
- **Capture now** — one frame through the capture abstraction, shown as a
  preview with dimensions, timestamp, source and tab info.
- **Record fixture (PNG)** — `chrome.downloads.download` of the last frame as
  `humanplay-<YYYYMMDD-HHMMSS>.png` (dev tool for building the fixture corpus;
  see `../test/fixtures/README.md`).
- **Server chip** — `GET http://127.0.0.1:8765/health` on open and on
  **Refresh**; `online · maia3-5m` / `server offline` (2.5 s timeout).

## Automated checks

From the repo root:

```bash
# drives the extension in Chrome for Testing via CDP: service worker, panel UI,
# chip state, toggle persistence, capture, fixture download, console cleanliness
node test/tools/capture-proof.mjs \
  --chrome "$HOME/.cache/humanplay-chrome/chrome/linux-155.0.8059.84/chrome-linux64/chrome" \
  --extension extension --page-url http://127.0.0.1:8765/pages/startpos.html \
  --manifest-all-urls --expect-chip online
```

`--manifest-all-urls` loads a temporary copy of the extension whose manifest
adds `<all_urls>` (the harness hash-compares every code file and reports
`codeIdentical`), because a headless browser cannot perform the toolbar click
that would grant `activeTab`. The shipped manifest is untouched.

## Boundaries

No Maia-3 code here, ever — the extension is a clean-room HTTP client for the
separate local server (`../docs/PROJECT.md`). No anti-detection features, no
Stockfish. Position recognition stays pixel-based; DOM scraping is test-only.

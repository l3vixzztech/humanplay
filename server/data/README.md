# server/data — bundled data tables

## `openings_eco.json`

ECO/opening names for the `/explain` response (`opening: {eco, name} | null`).

| | |
|---|---|
| **Source** | <https://github.com/lichess-org/chess-openings> (files `a.tsv` … `e.tsv`) |
| **Fetched** | 2026-10-17, upstream `master` |
| **License** | **CC0-1.0** (Public Domain Dedication) |
| **Bundled as** | one JSON file — no runtime dependency, no network at runtime |
| **Entries** | 3865 opening lines (see `count` in the file) |
| **Generated by** | `server/tools/generate_openings.py` (re-runs deterministically) |

### Provenance / license note

The upstream README states:

> As a collection of facts, this data set is in the public domain. Considerable
> effort was spent curating and cleaning the data. Insofar as that qualifies
> for copyright, the work is released under the CC0 Public Domain Dedication.

That is a clean, permissive license (no attribution required; we record it
anyway). **Verified 2026-10-17** before bundling, per the M8 brief ("bundle a
compact ECO/opening table ONLY after verifying its license is clean").

The file records the SHA-256 of every upstream TSV it was generated from, so a
future regeneration can be diffed against the recorded revision.

### Format

```json
{
  "version": 1,
  "source": "lichess-org/chess-openings (a.tsv..e.tsv), https://github.com/lichess-org/chess-openings",
  "license": "CC0-1.0",
  "generated": "2026-10-17",
  "source_sha256": { "a.tsv": "…", "b.tsv": "…", "…": "…" },
  "count": 3865,
  "openings": { "e4": ["B00", "King's Pawn Game"], "e4 e5 Nf3 Nc6 Bb5": ["C60", "Ruy Lopez"], "…": ["…", "…"] }
}
```

The key is the **SAN move sequence** of the opening's shortest line; trailing
check/mate markers (`+`/`#`) are stripped from both the table keys and the
runtime sequence. `explain_engine.opening_for_san()` matches the **longest
prefix** of the game's SAN sequence against these keys (the lichess-recommended
classification, restricted to move-sequence prefixes).

### Limitations (documented, by design)

* **Transpositions** reached by a move order that is not a prefix of any dataset
  line are not recognized (`opening: null`) — the honest answer.
* When the `/explain` request's base FEN is **not the standard start position**
  the pre-base moves are unknowable, so `opening` is **always `null`**
  (`explain_engine._is_standard_start`). The extension always sends the standard
  start position + the full replayed history, so real games always get a name.
* If the table file is missing, `/explain` degrades to `opening: null` (logged
  nowhere, no crash) — the commentary module is optional data.

### Regenerating

```bash
server/.venv/bin/python server/tools/generate_openings.py              # downloads the TSVs
server/.venv/bin/python server/tools/generate_openings.py --tsv-dir /path/to/tsvs
```
